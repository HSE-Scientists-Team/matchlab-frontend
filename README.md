# MatchLab Frontend

React-интерфейс администратора MatchLab — KAN-61. TypeScript, Vite, React Router и TanStack Query. Визуальный стиль продолжает экраны MatchLab: светлый фон, белые карточки, синие акценты и скругления. Есть адаптивная навигация для телефона.

## Возможности

- Обзор с текущими показателями, дневной активностью UTC, произвольным периодом до 366 дней и таблицей значений графика.
- Жалобы: активная и закрытая очередь, фильтры, назначение, решения, заметки, вложения и история.
- Достижения: очередь, архив решений, доказательства и проверенные редакции.
- Пользователи: поиск, блокировка/разблокировка и история.
- Проекты: детали, команда, роли, скрытие и восстановление видимости.
- Домены почты: создание, изменение, активация и история.
- Сотрудники: роли, включение/отключение, сброс пароля и отзыв сеансов.
- Аудит, собственный аккаунт и смена пароля.

Списки и истории имеют серверную пагинацию. Фильтры списков сохраняются в URL. Модератор не видит управление сотрудниками и формы изменения доменов; backend независимо проверяет все полномочия.

## Локальный запуск

Нужен Node.js 24 LTS.

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173/admin/. По умолчанию Vite проксирует API на http://localhost:8080, документацию — на http://localhost:8084. Пример конфигурации — .env.example.

Для проверки с рабочим API можно запустить:

```sh
MATCHLAB_API_PROXY_TARGET=https://api.matchlab.space npm run dev
```

Это настоящее API: выполняемые в интерфейсе изменения попадут в рабочую БД. Приложение не содержит тестового входа, встроенного токена, пароля или демонстрационных данных. Используется отдельный служебный аккаунт Admin.

## Контракт и поведение

Браузер обращается только к /api/v1/admin на своём origin. Снимок OpenAPI находится в api/admin.openapi.yaml, типы — в src/api/schema.d.ts.

```sh
npm run api:sync -- ../matchlab-backend/api/http/openapi.yaml
npm run api:generate
```

Без аргумента api:sync скачивает публичный контракт из https://api.matchlab.space/docs/openapi.yaml. CI проверяет соответствие типов зафиксированному снимку; он не требует живого API.

Сеанс хранится в sessionStorage конкретной вкладки и памяти, до срока backend. При выходе, истечении срока или 401 удаляются токен и кеш данных. Пароли не сохраняются; скачиваемые доказательства открываются по временной ссылке без referrer. Cookie-авторизация/BFF здесь не вводится: это отдельное развитие контракта backend.

Мутации не повторяются автоматически. При конфликте редакций или неизвестном результате отправки нужно сначала обновить карточку и проверить историю; повторная отправка до обновления заблокирована. Закрытие жалобы, блокировка пользователя и скрытие проекта остаются отдельными решениями.

## Проверки

```sh
npm run format:check
npm run build
npm test
npx playwright install chromium
npm run test:e2e
npm run test:container
```

Playwright проверяет desktop и mobile, авторизацию, права, фильтры, сохранение редакции, конфликты и явные boolean-поля. Браузерные проверки используют изолированный тестовый API, не обращаясь к рабочей БД. Проверки axe контролируют доступность; снимки создаются в игнорируемой папке test-results.

## Образ и доставка

Dockerfile собирает статические файлы и запускает непривилегированный Nginx на 8080. SPA доступна под /admin/, health probe — /healthz. GATEWAY_UPSTREAM по умолчанию http://gateway:8080, DOCS_UPSTREAM — http://api-docs:8080. Это серверные настройки; секреты приложению не нужны. HTML не кешируется, хешированные assets кешируются как immutable; добавлены CSP, запрет встраивания и nosniff.

```sh
docker build -t matchlab-frontend .
docker run --rm -p 8085:8080 -e GATEWAY_UPSTREAM=http://host.docker.internal:8080 -e DOCS_UPSTREAM=http://host.docker.internal:8084 matchlab-frontend
```

Actions → Build frontend image проверяет приложение и публикует приватный образ ghcr.io/hse-scientists-team/matchlab-services/frontend. По умолчанию включён propose_deploy: после успешной сборки создаётся PR в matchlab-infra, меняющий только FRONTEND_IMAGE в clusters/homelab/images.yaml. Остальные версии сохраняются. Слияние выполняется вручную, затем Flux обновляет Deployment. Отключите propose_deploy, если нужна только публикация образа.

Для создания PR нужен GitHub Actions Secret INFRA_REPO_TOKEN: fine-grained PAT с Resource owner HSE-Scientists-Team, доступом только к matchlab-infra, Contents и Pull requests: Read and write. Секрет используется только job создания PR; в образ и приложение не попадает. При истечении токена замените этот Secret. Deployment, registry credentials и Ingress /admin принадлежат matchlab-infra; frontend-приложению секреты не нужны.
